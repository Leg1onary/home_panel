# Дом — установка и подготовка панели

Home Panel 1.2.4. Интерьерная главная по референсу: крупный дом без сетки и рамки, компактное управление и подробная схематичная мебель. Формат настроек v3 и расширяемая модель устройств v1 сохранены: логическое устройство объединяет несколько каналов, не меняя их entity_id или разрешения команд. Подробности: [DEVICE_MODEL.md](DEVICE_MODEL.md). Для HA OS используй README в корне GitHub-репозитория и обновляй существующее приложение, не удаляя его.

При первом запуске создаётся база, каталог содержит устройства дома и планы расширения. Известные привязки профиля подставляются непроверенными; по умолчанию включён деморежим, реальные команды не отправляются. Существующая установка сохраняет свой режим, оформление и подтверждённые привязки.

## Запуск на Windows

1. Установи Node.js 22 или 24 LTS, если его ещё нет: [официальный сайт](https://nodejs.org/).
2. Распакуй весь установочный архив в новую пустую папку. Не запускай из ZIP. Не добавляй туда базы или настройки от предыдущих сборок.
3. Открой `Запустить.cmd`. При первом запуске устанавливается зависимость локального сервера, поэтому нужен интернет. Возможна установка нативного модуля SQLite; если установка не удалась, сохрани текст ошибки, не отключай защиту Windows.
4. После запуска откроется `http://127.0.0.1:8080`. Если браузер не открылся, используй `Открыть.cmd`.
5. Оставь окно сервера открытым. Остановка: Ctrl+C. Повторный запуск не сбрасывает базу.

Минимум Node.js 20.6; для нового развёртывания лучше 22/24 LTS. При занятом порте можно задать `PORT` в `.env`, а страницу открыть вручную с этим портом. `Открыть.cmd` рассчитан на стандартный 8080.

Обычный `py -m http.server` по-прежнему позволяет посмотреть дизайн, но не включает сохранение и адаптер. Двойной клик по `index.html` не поддерживается браузером из-за ES modules.

## Что сохраняется

- Тема, ночной режим, задержка ожидания, компактный экран.
- Избранные комнаты и их порядок.
- Каталог устройств: постоянные ID, названия, типы, зоны, порядок, примечания, установленное / планируемое оборудование.
- Модель устройств v1: группы каналов, названия приборов, основная комната и отдельные метаданные будущего плана.
- Привязки entity_id и включение световых устройств в мастер-выключение.
- Выбранный источник данных: демо или Home Assistant.
- Фото только после отдельной кнопки «Сохранить фото на этом компьютере».

Хранилище: `data/panel.sqlite` рядом с локальным сервером. Оно общее для этой локальной установки; несколько вкладок используют одну конфигурацию. Автосохранение отображает подтверждение или ошибку. Не закрывай страницу, пока видно «Сохраняем».

Состояния устройств, температуры, журнал команд и тестовые неисправности не сохраняются как актуальные. Рабочий режим после перезапуска начинает с «Нет данных» и ждёт Home Assistant.

В приватном облачном превью настройки хранятся на сервере превью с разделением по идентификатору посетителя. Не рассчитывай на превью как на постоянный домашний сервер: его хранилище зависит от срока жизни среды. Фото там можно посмотреть только во вкладке; постоянное сохранение в облаке запрещено. Локальная и облачная конфигурации автоматически не синхронизируются.

## Повседневное управление

- Главная: часы, интерьер, до шести избранных комнат, температура гостиной, скважина и чердак, карточка Дуо Макс.
- Свет: отдельные каналы каждой комнаты.
- Мой дом: условная объёмная модель по предоставленному плану. Загрузка только при открытии, отрисовка по изменениям.
- Обзор: сгруппированные датчики и камеры. Нажатие «Двор» или карточки камеры открывает WebRTC-видео с HLS как резервом; снимок доступен отдельно.
- Инженерия: ворота, котёл и питание насоса. Только наблюдение, все команды заблокированы на сервере.
- Ожидание: по таймеру или вручную. Первое касание только пробуждает экран.
- Ночной интерфейс: 22:00–07:00 МСК или вручную. Не меняет аппаратную яркость и домашнее освещение.
- Полный экран: кнопка или F11. В некоторых превью/iframe браузер запрещает fullscreen API; панель показывает подсказку вместо сбоя.

Компактный режим уменьшает служебное оформление. Он не является защитой от выхода из браузера или доступа к настройкам. Настройку автозапуска системы и отдельного планшета выполняем после выбора домашнего устройства.

## Фото

JPEG, PNG или WebP до 10 МБ и 24 мегапикселей. В браузере фото преобразуется в JPEG с длинной стороной до 2048 px, без исходных EXIF-метаданных. Результат до 2 МБ сохраняется только по отдельной кнопке в локальную SQLite-базу. Новый выбор без сохранения действует только во вкладке; предыдущая сохранённая фотография остаётся до явного сохранения нового изображения или сброса.

Интерьер по умолчанию является визуальным референсом, не фотографией дома.

## Технический раздел

Открывается из настроек панели. Здесь источник данных, логические устройства, каталог каналов, привязки, диагностика, копия JSON и план проверки на месте. Это отдельный раздел интерфейса, не защищённая админка.

Исходные комнаты и планировка описаны в `config/house.json`; изменение геометрии 3D-модели требует пересборки. Устройства в существующих комнатах и зонах добавляются и изменяются через «Каталог» без пересборки: свет, RGB (новые RGB пока включение/выключение), температура, влажность, освещённость, открытие, дым, движение, протечка, камеры и инженерные карточки. Всего до 128 записей. Зоны также включают чердак, скважину и двор.

Каждая клавиша многоклавишного выключателя является отдельной световой записью. Постоянный ID не зависит от порядка устройств или их названий. Тип созданной записи не меняется; при ошибке создай новую. Перенос между зонами или смена наличия снимает отметку проверки. Переименование и порядок сами по себе привязку не меняют. Новые и планируемые записи не могут автоматически получить право управления.

Сводка климата использует первый установленный датчик температуры и влажности соответствующей зоны в порядке каталога. Перенесённый датчик не остаётся показанием прежней комнаты. При нескольких датчиках одной зоны основной можно поднять выше в каталоге.

Начальные резервы: два будущих выключателя коридора, две дополнительные камеры и откатные ворота. Это не утверждение, что оборудование установлено. Если выключатель будет двухклавишным, добавь вторую линию отдельно. Потолочная лента ванной по-прежнему запланирована и недоступна.

Копия JSON v3 включает оформление, избранное, каталог, entity_id и модель устройств v1. Старые копии v3 без модели также принимаются. Она не включает токен, фото или состояния устройств. Импорт включает деморежим и снимает все отметки физической проверки, даже если в копии было `verified: true`. Неверный формат отклоняется без применения.

В установочном архиве нет готовой базы, сохранённых фото, реальных токенов или тестовых привязок. При первом запуске сервер сам создаёт `data/panel.sqlite`. Резервные копии пригодятся после того, как ты начнёшь настраивать эту установку.

Для полной локальной резервной копии: останови сервер и скопируй папку `data`. Файл `.env` содержит секрет и требует отдельного защищённого хранения; его нельзя присылать в чат или включать в общий архив.

## Home Assistant: подготовлено, но ещё не подключено

Адаптер использует получение состояний через `GET /api/states` и управление через `POST /api/services/<domain>/<service>`, согласно [REST API Home Assistant](https://developers.home-assistant.io/docs/api/rest/). Он не записывает фиктивные состояния через `POST /api/states`.

Состояния запрашиваются раз в 5 секунд. Изменения через Алису или другой интерфейс отобразятся после следующего опроса, если соответствующие сущности реально доступны в Home Assistant. При ошибке связи демоданные не подставляются.

Команда считается подтверждённой только после наблюдения ожидаемого состояния сущности. Это подтверждение состояния Home Assistant, не независимая проверка физического света или работы оборудования. После тайм-аута команда могла выполниться; автоматического повторения нет.

### На месте

1. Заверши первоначальную настройку Home Assistant и интеграции.
2. На локальном компьютере скопируй `.env.example` в `.env`.
3. Укажи фактический `HA_URL` и `HA_TOKEN`. Токен создаётся в профиле Home Assistant; см. [официальное описание авторизации](https://developers.home-assistant.io/docs/api/rest/). Не вводи токен в панель, переписку или файлы сборки.
4. Перезапусти локальный сервер.
5. В техническом разделе загрузи список сущностей.
6. Начни с двух линий гостиной. Физически проверь соответствие, задай entity_id, отметь проверку и сохрани.
7. Включи рабочий режим и проверь команду, внешнее изменение состояния, потерю связи и восстановление.
8. Только после этого привязывай остальные каналы и датчики.

При проверке привязок сервер проверяет существование сущности и домен. Для температур нужны °C, влажности %, для двери соответствующий device_class, для дыма smoke. Один entity_id не разрешено назначать двум слотам.

По умолчанию ни одна привязка не задана и не проверена. Адрес, реальные entity_id и токен не угадываются.

### Ограничения безопасности

- Разрешены команды только проверенных линий света и RGB-лампы.
- Насос, котёл и ворота исключены из команд серверного адаптера даже после проверки привязки. Пока допускается только получение состояний. Планируемый свет также заблокирован.
- Камера получает HLS-видео или отдельный кадр через настроенный сервер Home Assistant по нажатию. При закрытии окна и скрытии страницы плеер останавливается; upstream HA может завершиться позднее по своему idle timeout. Произвольные URL и RTSP-адреса не принимаются каталогом. Supervisor token, токен камеры и исходный адрес HLS не передаются браузеру. В приватном превью доступ к настоящим камерам выключен.
- Прихожая: левый канал питает её свет и RGB; правый канал управляет террасой. RGB-команда требует подтверждённого питания прихожей.
- RGB-яркость и цвет требуют заявленной поддержки соответствующей функции. Поддержка цвета в текущем адаптере ограничена rgb.
- Xiaomi Hub 2 не считается светильником.
- Насос не входит в мастер-свет; две карточки Yeelight в Алисе не означают два насоса.
- Для световых записей мастер-выключение можно отключить в каталоге. Никакое инженерное оборудование невозможно добавить в мастер-свет подменой настроек.
- Дуо Макс в рабочем режиме не получает выдуманных play/volume-команд. Условное управление доступно только в демосимуляторе.

## Что осталось сделать в доме

- Завершить настройку Home Assistant, определить реально доступные сущности Яндекса, Xiaomi и Tapo. Наличие устройства в Алисе не означает, что его сущность уже доступна этому адаптеру.
- Указать адрес и токен только на локальном сервере; проверить свет гостиной, прихожую / террасу и зависимость питания RGB.
- Подключить датчики; подтвердить единицы и соответствие реальным устройствам.
- Проверить получение настоящего кадра Tapo через Home Assistant, затем добавлять остальные камеры.
- Для ворот узнать модель привода, допустимый интерфейс, наличие датчиков положения, фотоэлементов и защит. До этого управление не разблокируется.
- Для Kentatsu найти точную модель и документированный внешний интерфейс. ESP32 или другой модуль обсуждается только для разрешённого внешнего управления после проверки специалистом, не для газового клапана, горелки или защитной цепи.
- Выбрать постоянный узел размещения панели и экран киоска; настроить безопасный доступ с другого устройства и автозапуск.

Этот архив запускает сервер панели на Windows с Node.js. Он не является дополнением Home Assistant OS и не устанавливается на HAOS запуском `.cmd`. Вариант размещения рядом с HAOS или на отдельном узле подберём отдельно; сетевой доступ сейчас намеренно не открыт. Работоспособность реальных домашних интеграций ещё не проверена.
- Камера пока без изображения. Трансляцию и способ доступа проверяем отдельно в доме.
- Свежесть температур: тестовая политика 30 минут; в реальном доме её нужно согласовать с частотой отчётов датчиков. Время пакета использует last_reported, если доступно, иначе last_updated.
- Панель не заменяет автономную пожарную сигнализацию или автоматику безопасности.

## Локальная безопасность и сеть

Сервер слушает только `127.0.0.1`, без LAN-доступа и проброса в интернет. Файлы `.env`, SQLite и серверный код не выдаются через HTTP. Изменяющие запросы защищены ключом, полученным при запуске страницы, и проверкой происхождения локальных запросов. Токен хранится только в окружении серверного процесса.

При локальном HTTP-подключении к Home Assistant токен идёт по доверенной локальной сети без TLS. Не используй этот режим через публичную сеть. Для отдельного планшета, удалённого доступа и эксплуатации вне localhost нужно отдельно выбрать защищённое размещение и авторизацию; просто открыть порт нельзя.

Локальные шрифты и изображения входят в пакет, после первой установки интернет для показа интерфейса не требуется. Работа реальных устройств всё равно зависит от их интеграций и доступности Home Assistant.

## Разработка и проверка

```bash
npm ci
npm run build
./node_modules/.bin/esbuild tests/catalog.mjs --bundle --platform=node --format=esm --outfile=/tmp/panel-catalog-test.mjs
node /tmp/panel-catalog-test.mjs
node tests/integration.mjs
```

Результаты:

- `dist`: статические файлы для превью.
- `release`: локальная установка с сервером, launchers, package.json, README и статической сборкой.
- `server`: исходники сервера и HA-адаптера.
- `src/preferences.js`: общая валидация конфигурации.
- `src/catalog.js`: типы, постоянные ID, начальный каталог и серверные ограничения возможностей.
- `tests/catalog.mjs`: валидация каталога v3 и отказ от несовместимых копий.
- `tests/integration.mjs`: изолированные backend-тесты с имитацией Home Assistant.

Для локальной разработки после сборки:

```bash
node release/server.mjs
```

Сборка интерфейса ESM; Three.js в отдельном ленивом chunk. Локальный сервер Node.js, хранение SQLite через better-sqlite3. Шрифт Manrope поставляется с лицензией SIL OFL в `assets/manrope-license.txt`.

В среде разработки проверены backend и браузер Chromium. Windows cmd, реальные устройства, физический kiosk и возможности конкретных интеграций требуют проверки на твоём оборудовании.
