# Home Panel для Home Assistant OS

Версия надстройки: 1.0.1. Порт: 8090. Пакет предназначен для системника amd64 с Home Assistant OS; дизайн и 3D-модель не изменены.

## Что исправлено

- Убрана ссылка на несуществующий готовый образ: надстройка собирается локально из Dockerfile.
- Исправлены пути COPY: package.json, package-lock.json, server.mjs, startup.mjs и dist находятся в корне home_panel.
- Зависимости устанавливаются при сборке, а не при каждом запуске.
- Демопревью сервера выключено, браузеры домашней сети могут обращаться к API панели.
- Тема, избранное, привязки и загруженное фото сохраняются в SQLite: `/data/homepanel/panel.sqlite`. В браузере секреты не хранятся.
- Связь с HA настроена через `homeassistant_api` и автоматически выданный Supervisor token. Создавать персональный долгоживущий токен не нужно ([документация HA](https://developers.home-assistant.io/docs/add-ons/communication/)).

## Установка

### Скопировать пакет

1. Скачай именно новый архив и распакуй на обычном компьютере.
2. Открой WinSCP или другой SFTP/SCP-клиент с уже настроенными параметрами Terminal & SSH. Используй тот же логин, пароль/ключ и порт, с которыми SSH уже работает; ничего в HA не перенастраивай.
3. В `/share` создай папку `home-panel-package`.
4. Скопируй в неё папку `home_panel` целиком и файл `install-home-panel.sh`.

Должно получиться:

```text
/share/home-panel-package/
├── install-home-panel.sh
└── home_panel/
    ├── config.json
    ├── Dockerfile
    ├── package.json
    ├── package-lock.json
    ├── server.mjs
    ├── startup.mjs
    └── dist/
```

Не нужно копировать repository.json. Нельзя добавлять `/addons` или `/local_apps` в список URL репозиториев.

### Установить локальное приложение

В уже работающем Terminal & SSH выполни:

```sh
sh /share/home-panel-package/install-home-panel.sh
```

Скрипт использует доступный каталог `/local_apps` либо `/addons`. Он копирует только исходники надстройки и не трогает базу данных Supervisor. Если каталога нет, скрипт остановится с сообщением, а не создаст папку в неправильном месте.

В Home Assistant открой **Настройки → Приложения → магазин / Установить приложение → ⋮ → Проверить обновления**, затем обнови страницу. В разделе локальных приложений появится **Home Panel**; схема локального размещения и обновления магазина описана в [официальном руководстве](https://developers.home-assistant.io/docs/add-ons/tutorial/).

1. Открой Home Panel; проверь версию **1.0.1**.
2. Нажми **Установить**. Системник скачает базовый Node-образ и соберёт зависимости; первый запуск установки требует интернета. Длительность зависит от железа и сети, фиксированное время не обещаем.
3. Включи **Запуск при загрузке** и, при желании, **Watchdog**.
4. Нажми **Запустить** и открой журнал.
5. После строки `Panel ready: port 8090` открой на планшете или ПК:

```text
http://192.168.8.182:8090
```

Если старая ошибочная надстройка уже установлена, сначала обнови исходники этим скриптом, обнови магазин и используй **Обновить** / **Пересобрать**, доступные в интерфейсе приложения. Не удаляй установленную надстройку ради обновления: удаление может удалить её данные. Если нужной кнопки нет, сначала пришли скрин страницы приложения.

## Подключить реальные устройства

Панель начинает с явно обозначенного деморежима и пустых привязок. Наличие надстройки не означает, что все выключатели уже настроены.

1. Открой настройки панели → технические настройки / подключение дома.
2. Во вкладке **Связь** выбери **Home Assistant · реальные состояния**.
3. Во вкладке **Привязки** выбери существующие сущности HA для нужных каналов; сначала одну проверенную линию света.
4. Не выбирай кнопочные события «верхняя/нижняя кнопка» вместо сущности выключателя. Для управления нужны light/switch со состоянием on/off.
5. Отметь проверенную привязку и сохрани. Сервер дополнительно проверит существование и тип сущности.
6. Назначь камеру двора существующей сущности camera. В этой версии панель показывает кадры из HA по запросу, не непрерывный mainstream-поток ONVIF.
7. Назначь температуре/влажности только датчики с доступными состояниями; отсутствующие значения не выдаём за норму.

Реле насоса в этот запуск не подключаем. Управление газовым котлом и воротами также не включено.

## Сохранение и обновления

Настройки общие для домашней панели, сохраняются на сервере, не в localStorage. После выбора темы дождись сообщения о сохранении, обнови страницу, затем перезапусти приложение и проверь тему.

HA предоставляет `/data` как постоянное хранилище приложения; при обновлении образа следует сохранять данные вне его файловой системы ([описание конфигурации приложения](https://developers.home-assistant.io/docs/add-ons/configuration/)). Штатное обновление не должно стирать базу, но это не заменяет резервную копию: включай Home Panel в резервные копии HA и сохраняй JSON-копию из панели. Удаление надстройки, ручное удаление `/data` или очистка настроек может их уничтожить.

Порт 8090 предназначен только для доверенной домашней сети. Панель не имеет отдельного пользовательского входа: любой допущенный к ней клиент домашней сети сможет управлять проверенными линиями и менять настройки. Не пробрасывай порт в интернет или гостевую сеть. CORS `*` и правки `configuration.yaml` для этого пакета не нужны; если раньше добавил wildcard только ради панели, он не используется этой схемой.

## Проверки и ограничения

Проверены локальные runtime-тесты серверного кода на Node.js 20 и 22: сохранение темы/избранного/привязок после перезапуска, общий профиль для клиентов, работа API с LAN-заголовками, запрет чужого Origin и запросов без защитного ключа, отправка команды и чтение подтверждённого состояния, получение кадра камеры, корректные пути `/core/api`, обработка неверной авторизации и отсутствие токенов в ответах. На Node.js 22 выполнена установка зависимостей по package-lock с реальным нативным модулем SQLite.

В браузере проверены переключение и сохранение темы после обновления страницы, загрузка списка сущностей, проверенная привязка одной линии и выключение света с подтверждением от тестового HA. Светлая и тёмная темы просмотрены на 1440 px, мобильная раскладка на 375 px: ошибок JavaScript и горизонтального переполнения в проверенных сценариях не обнаружено. Тестовые сущности и токены в архив не включены.

Docker/Supervisor в среде подготовки отсутствуют: полная Docker-сборка и установка на реальный HA OS здесь не выполнены. Финальная проверка контейнера происходит при установке на системнике; при ошибке присылай журнал установки/запуска без секретов. Это ограничение проверки, а не утверждение, что контейнер уже работает у тебя.
